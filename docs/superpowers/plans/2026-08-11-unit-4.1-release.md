# Unit 4.1 Axis Load Cases Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release axis-load-cases@0.1.0 using ID39 and ID42 as the accepted Unit 4.1 historical evidence, while explicitly deferring the unavailable third live-project fixture.

**Architecture:** Preserve the existing pure module package and generic module runner. Complete the missing immutable-source records, optional trace-only context ports, validation evidence, conformance checks, sealed entry point, generated registry, and release documentation. Duty cycle and ambient temperature are recorded in the calculation trace but never alter the per-case rigid-body force equations.

**Tech Stack:** TypeScript, Vitest, Zod, the MachineStudio module SDK and source registry, generated TypeScript registry, Markdown release records, npm scripts.

---

## Release invariants

- ID39 and ID42 are release-candidate historical regression evidence, not release-grade vendor validation.
- Their source phases stay unclassified and every documented discrepancy remains visible.
- The third long-stroke/high-speed real-project fixture remains a deferred Unit 0.1 / Phase 1B validation item; no synthetic replacement is permitted.
- Version 0.1.0 supports only normal and peak cases. Holding and emergency-stop behavior remains unsupported.
- Duty cycle and ambient temperature are optional trace-only context. They must not change force or moment outputs.
- The final conformance report must contain no skipped import-boundary or source-immutability check.
- A hash mismatch, source-registration mismatch, test failure, documentation/runtime inconsistency, or dirty generated registry blocks release.
