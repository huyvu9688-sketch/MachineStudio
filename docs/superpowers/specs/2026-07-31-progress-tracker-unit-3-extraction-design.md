# Unit 3 Progress Context Extraction

## Goal

Keep the complete progress history while making continuation work for
Milestone 3 small and targeted to read.

## Structure

- `context/progress/unit-3.md` will contain every Unit 3.1 through Unit 3.4
  record currently in `context/progress-tracker.md`, plus the Unit 3.5
  next-work-unit brief.
- `context/progress-tracker.md` will retain all non-Unit-3 history and replace
  moved material with concise links to `context/progress/unit-3.md`.
- `CLAUDE.md` and `context/ai-workflow-rules.md` will direct normal Unit 3
  continuation work to the small Unit 3 file. Full audits will read both the
  tracker and the Unit 3 file.

## Content Rules

- Relocate historical Unit 3 information without changing its meaning.
- Keep the new file self-contained: current status, Units 3.1–3.4 history,
  standing deferrals, decisions, and Unit 3.5's requirements/exit criteria.
- Keep cross-cutting history and non-Unit-3 information in the master tracker.
- Future Unit 3 updates go to `context/progress/unit-3.md`; audit summaries
  in the master tracker link to the latest state rather than duplicating it.

## Verification

- Confirm every Unit 3.1–3.4 tracker reference is either relocated or
  represented by a pointer to the new file.
- Confirm normal read-order instructions do not require the large tracker for
  Unit 3 continuation work.
- Confirm the current next work unit remains Unit 3.5.
