# Roadmap

## How phases map to milestones

This file plans in **phases**. `context/implementation-map.md` and
`context/progress-tracker.md` execute in **milestones and units**. Same
work, two labels:

| Roadmap phase | Milestone |
| --- | --- |
| 0A, 0B, 0C | 0, 1, 2 |
| 1A | 3, 4 |
| 1B, 1C | 4 (later units) |
| 1D | 5 |
| 2 and later | after MVP |

## Product Strategy

The MVP is a complete linear-axis engineering workflow for machines
delivered to the US and Japanese markets. The
roadmap prioritizes end-to-end credibility over the number of calculators.
Additional modules may be added only when the shared contracts remain
consistent and the active workflow gate is not weakened.

## Module Prioritization

Score every candidate module before committing to it:

`priority = usage frequency x manual pain x workflow leverage / data cost`

- Usage frequency: how many of the last 10 machines required it
- Manual pain: 1 to 5, based on time and error risk
- Workflow leverage: 1 to 5, based on how many other modules depend on it
- Data cost: 1 to 5, based on catalog and validation difficulty

Re-score before each expansion milestone.

## Module Definition of Done

A module ships only when all items pass:

1. Released manifest with stable module ID, semantic version, SDK range,
   package hash, and validity envelope
2. Inputs and outputs declared against released canonical parameters
3. Pure, deterministic, unit-aware compute function
4. Structured calculation trace generated by the compute path
5. Failures, warnings, assumptions, and validity checks defined
6. At least three published reference examples reproduced within stated
   tolerances
7. Boundary and invalid-input tests
8. Dimensional and serialization tests
9. At least one independent benchmark source or tool comparison
10. Validation record documenting methods, sources, editions, deviations,
    reviewer, and supported use limits
11. Generic UI schema and report schema pass conformance validation
12. Optional manufacturer-part schema and matching adapter validated
13. Cross-module link compatibility tests pass
14. Workflow integration tests pass when the module participates in a
    guided workflow
15. Registered through the module registry without core-engine, generic
    UI, generic report, or database-schema modification
16. Build, lint, typecheck, test, and progress documentation pass

## Phase 1B — Mechanical Transmission

Modules:

- Ball screw and screw support
- Linear guide
- Coupling
- Support bearings

Catalog support:

- Manufacturer part revision import
- Hard filters and transparent ranking
- Required-spec output
- Lightweight component assignment

Gate:

- Horizontal, vertical, long-stroke, and high-speed cases validate — **not
  yet met.** `ball-screw@0.1.0` and `linear-guide@0.1.0` released
  2026-08-12 (each own Module Definition of Done items are complete —
  published manufacturer reference examples, independent-benchmark
  comparisons — see `validation/ball-screw/0.1.0.md` and
  `validation/linear-guide/0.1.0.md`), but no historical machine project's
  own case has been run through either module; this Gate item is a
  Phase 1B / Unit 5.4 milestone-level requirement, exercised once a
  complete `linear-axis@1` chain runs a real historical case end to end.
- Screw buckling, critical speed, life, and guide moment-loading checks
  are demonstrated — **met.** `ball-screw@0.1.0` and `linear-guide@0.1.0`
  both released 2026-08-12; see `context/implementation-map.md` Unit 4.3
  and Unit 4.4 "Gate".
- Assigned components become stale when their supporting run changes

## Phase 1C — Servo Drive Train

Modules:

- Servo motor
- Optional gearbox
- Drive/amplifier compatibility
- Holding brake
- Regeneration and duty-cycle checks

Gate:

- Peak torque, RMS torque, speed, inertia, brake, drive, and regeneration
  are validated against independent methods and manufacturer tools —
  **partially met.** `drive-train@0.1.0` released 2026-08-12
  (`validation/drive-train/0.1.0.md`); peak torque, RMS torque, speed, and
  inertia (ratio) are validated against Omron's and THK's own manufacturer
  worked examples and an independent per-phase RMS-torque calculation (see
  `context/implementation-map.md` Unit 4.7 "Gate") — but **brake and drive
  are not validated at all, and regeneration only partially**: holding-
  brake torque is a reported catalog value with no check or comparison;
  drive/amplifier current and voltage compatibility is out of scope
  entirely, blocked on a generic-engine electrical-current dimension this
  project does not have yet; regenerative energy is checked under a stated
  "100% efficient absorption" simplifying assumption, corroborated only in
  formula shape by Celera Motion's own resistor-sizing method, with no
  worked numerical example reproduced. These three remain open scope gaps
  for a future module version, not a release blocker for `0.1.0`.
- A complete compatible drive-train set can be assigned to an axis — **not
  yet met.** This is Unit 5.4 (end-to-end MVP validation) / application-
  layer territory: all seven `linear-axis@1` roles now have a registered
  module (`axis-load-cases@0.1.0` through `drive-train@0.1.0`, all released
  by 2026-08-12), so Unit 5.4 is unblocked, but no complete drive-train set
  has actually been assigned to a real axis in the application yet.

## Phase 1D — Guided Linear-Axis MVP

Deliverables:

- `linear-axis@1` guided workflow
- Complete candidate system comparison
- Multi-level BOM
- Module, assembly, and machine HTML reports
- Requirements verification matrix
- Immutable machine baseline and comparison
- Append-only audit history

Gate:

- One live linear axis is completed without the original spreadsheet —
  **partially met.** Unit 5.4 Scenario 1 (2026-08-12,
  `validation/unit-5.4/scenario-1-horizontal-axis.md`) ran a real
  horizontal axis end to end through the complete `linear-axis@1.0.0`
  workflow — all seven modules, a full checked part selection, a generated
  BOM/report, and a reproduced baseline — without any spreadsheet. It is
  not yet a full "live linear axis" in the sense this gate means: only
  `axis-load-cases`'/`motion-profile`'s own inputs have real historical
  (ID39) evidence behind them, every other module's own catalog data is
  disclosed representative data, not one real machine's own complete BOM
  (see that record's own "Disclosed Limitations"), and Scenarios 2/3 remain
  blocked on evidence — see `context/implementation-map.md` Unit 5.4.
- All assigned calculated components link to supporting runs — **met for
  Scenario 1's own six assigned parts** (each cites its own module
  instance's `CalculationRun`, `validation/unit-5.4/
  scenario-1-horizontal-axis.md` "Assigned Parts").
- Baseline remains reproducible after newer modules and catalog imports —
  **baseline reproduction itself demonstrated** (Scenario 1's own baseline
  reloads with every module ref `pass`/not-stale); reproducibility *after a
  later module or catalog change* is not yet separately exercised.
- Founder accepts the workflow as a practical replacement — **not yet
  assessed.**

## Phase 4 — Safety Support and Review Workflow (US and Japan)

- ANSI B11-oriented risk assessment support (US)
- MHLW comprehensive-safety-guideline risk assessment support with JIS
  B 9700 methodology references (Japan)
- Safeguarding and safety-function records
- OSHA machine guarding and hazardous-energy checklists
- Functional safety calculations only after separate validation planning
- Review states and multi-user permissions

The phase supports engineering documentation; it does not claim authority
or certification.

Gate:

- One machine safety documentation package is produced and independently
  reviewed by a qualified engineer

## Phase 5 — Production Feedback

- Production count and stop-log import
- Designed versus actual cycle-time comparison
- OEE-lite indicators
- Issue feedback to design assumptions

Gate:

- One commissioned machine is compared against its design baseline

## Explicitly Deferred

- Market profiles beyond the United States and Japan
- PLC, OPC UA, and live machine connectivity
- CAD, PDM, PLM, and ERP integrations
- Multi-tenant organizations and enterprise approvals
- Public or licensed catalog redistribution
- Runtime third-party module marketplace
- General FEA, multibody simulation, or symbolic mathematics
