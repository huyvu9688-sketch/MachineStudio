## Purpose and Supported Applications

Given a load (mass, incline angle, friction coefficient, optional
extend-stroke process force), a required stroke, three load-offset lever
arms (roll/pitch/yaw), and the engineer's own operating pressure,
force-sizing load factor, cushion type, mounting style, and buckling safety
factor, this module computes the required extend/retract force and
required resultant moment, then ranks real SMC MGQ/MGP catalog guided-
cylinder candidates against that requirement (theoretical force, stroke
range, allowable lateral load where a discrete rating exists, allowable
rotational torque of the guide plate, and piston-rod buckling) via
`lib/application/catalogs/guided-cylinder-matching.ts`. See
`context/modules/guided-cylinder-sizing/stage-1-spec.md` "Purpose".

## Validity Envelope and Assumptions

- One load, one installation, one required stroke — not a multi-cylinder
  system, dual-rod, table-cylinder, or rodless variant (each is a separate,
  later module; design doc "Sequencing"/"Out of Scope").
- No load case (`normal`/`peak`/etc.) semantics — every input is a single
  engineer-supplied value per calculation run.
- Required-force resolution is identical to `pneumatic-cylinder-
  sizing@0.1.0`'s own forward/return sign convention, reproduced
  independently.
- Required-moment resolution (new): `M_axis = F_req,ext * offset_axis` for
  each of roll/pitch/yaw, combined as a Euclidean sum
  (`sqrt(M_roll^2+M_pitch^2+M_yaw^2)`). **This combination method is this
  module's own engineering assumption, not a value either fetched SMC
  catalog documents** — neither MGQ nor MGP gives guidance on combining
  independently-computed moments against its own single published
  allowable-torque figure (`stage-1-spec.md` "Moment Resolution",
  `stage-2-contract.md` Decision 5). A disclosed `0.1.0` limitation.
- Force capacity and buckling are evaluated per-candidate using formulas
  reproduced independently from `pneumatic-cylinder-sizing@0.1.0`'s own
  kernel (not imported, per ADR-0011's reuse policy).
- **Allowable lateral load is checked for MGQ candidates only.** MGP's own
  fetched catalog publishes a plate-displacement stiffness graph for the
  equivalent data, not a discrete allowable-load rating — a real, confirmed
  cross-series catalog gap (`stage-1-spec.md` correction 2), not a module
  scope choice. A candidate with no seeded `allowable_lateral_load`
  attribute skips this check (treated as not applicable), rather than being
  rejected for missing data.
- **Cushion kinetic energy is reported only, not checked against a
  candidate.** Neither the MGQ nor the MGP catalog publishes a discrete
  allowable-kinetic-energy figure by bore/cushion-type — both give a
  load-mass-vs-speed graph instead (`stage-1-spec.md` correction 5), a real
  gap the design doc did not anticipate.
- **No mounting-style catalog attribute or `MatchCriterion`** — a guided
  cylinder's guide plate, not its rod end, is the primary mechanical mount;
  neither catalog publishes the rod-end-fixity taxonomy
  `pneumatic-cylinder-sizing@0.1.0`'s own `mounting_style` check assumes
  (`stage-1-spec.md` correction 6). `pneumatic.mounting_style` stays a
  required input feeding the buckling end-fixity formula only.
- Piston-rod buckling uses the same generic (non-pneumatic-manufacturer-
  sourced) Euler column formula and four end-fixity cases
  `pneumatic-cylinder-sizing@0.1.0`'s own kernel already established.
- The seeded SMC MGQ/MGP catalog (`reference/catalog-seed/
  smc-mgq-mgp.csv`, 40 rows — 20 MGQ + 20 MGP, one row per bore x bearing
  type) is a representative dataset drawn from SMC's own published
  catalogs, for the founder to review and trim to their real working set —
  not a claim that every row is a part the founder actually stocks. The
  allowable lateral load and torque figures are genuinely stroke-dependent
  in SMC's own tables; each seeded row uses its own minimum populated
  stroke as one representative, conservative figure, not the full
  per-stroke table (`scripts/seed-guided-cylinder-catalog.mts` header).

## Reference Examples (Published Worked Examples)

### Example 1 — SMC MGQM40, reached via a load with roll/pitch/yaw offsets

- Source: `jp.smc.mgq_series_catalog@web-2026-08-26`, MGQM40 (40 mm bore,
  slide bearing, 50 mm stroke) dimensional/rating data
- Inputs: a 10 kg vertical lift (`incline_angle = 90 deg`), zero friction,
  zero process force, roll/pitch/yaw offsets of 10/5/0 mm
  (`smc-reference-example.ts`, `runMgqm40Example`)
- MachineStudio result: `required_extend_force = 98.0665 N`,
  `required_moment ~= 1.096 N*m`. The MGQM40 candidate (rod 16 mm)
  clears every checkable requirement: theoretical extend force
  `F1 = eta*A1*P ~= 439.8 N` (via this module's own reproduced
  `resolvePistonAreas`/`resolveTheoreticalForce`) exceeds the required
  98.0665 N; the catalog's own `167 N` allowable lateral load exceeds it;
  the catalog's own `3.43 N*m` allowable rotational torque exceeds the
  required 1.096 N*m moment; the permissible compressive (buckling) load
  at this short 50 mm stroke vastly exceeds the required force.
- Tolerance applied and why: quantitative for the force/moment figures
  (within 1e-3 N / 0.01 N*m of hand calculation); qualitative for the
  per-candidate checks (each individually clears the requirement, matching
  the real MGQM40 catalog candidate)
- Pass / fail against tolerance: **pass**

**This module has one reference example, not three** — the same "satisfied
by reference, not independently re-met a second time" treatment
`pneumatic-cylinder-sizing@0.1.0`'s own validation record already used: the
theoretical-force and buckling formula bodies are
`pneumatic-cylinder-sizing@0.1.0`'s own already-validated formulas
(themselves reused from `pneumatic-cylinder@0.1.0`'s own three published
worked examples), reproduced byte-for-byte identical and reused by
citation. This module's own genuinely new surface — the required-moment
resolution and the allowable-lateral-load/torque catalog checks — is
verified by the reference example above plus the DB-gated catalog-matching
fixture in `lib/application/catalogs/load-component-assignment-view.
test.ts`, which reproduces this exact MGQM40 scenario end to end.

## Independent Method or Tool Comparison

**Satisfied by reference, not re-derived, for the reused formula areas.**
The theoretical-force and buckling formulas are reused/reproduced unchanged
from `pneumatic-cylinder-sizing@0.1.0`, which already cites
`pneumatic-cylinder@0.1.0`'s own completed Norgren M/1000 independent
benchmark (2 of 4 formula areas closed) for the theoretical-force formula
area — confirmed byte-for-byte identical by this module's own
`math.test.ts` against `pneumatic-cylinder-sizing@0.1.0`'s own
`math.test.ts` fixtures.

**The new required-moment resolution has no manufacturer method to
benchmark against.** It is ordinary statics (`M = F*d`) plus a disclosed
Euclidean-sum combination assumption neither fetched SMC catalog
documents. Verified instead by property tests in `math.test.ts`: each axis
moment scales linearly with its own offset and with the lateral force; the
combination is zero when either the force or every offset is zero; the
resultant is monotonically non-decreasing in each offset — the same
"property tests substitute for a manufacturer benchmark on genuinely new,
unsourced physics" treatment `pneumatic-cylinder-sizing@0.1.0`'s own
required-force resolution received.

### What this closes and what it does not

Carries forward `pneumatic-cylinder-sizing@0.1.0`'s own evidence-gap split
for the theoretical-force and buckling formula areas (closed via citation
for theoretical force; buckling remains without a second independent
source). Cushion kinetic energy has no candidate check at all in this
module (correction 5) — not applicable to benchmark. The moment-combination
method is new and has no benchmark of any kind, disclosed as this module's
own engineering assumption throughout.

## Tolerances and Deviations

- Reproduces every disclosed evidence gap `pneumatic-cylinder-sizing@0.1.0`
  already carries for the force/buckling formula areas — not silently
  resolved here.
- The moment-combination method (Euclidean sum) is a new, undisclosed-by-
  SMC engineering judgment call unique to this module.
- Allowable lateral load is checked for MGQ candidates only — a real,
  confirmed cross-series catalog gap, not a module scope choice.
- Cushion kinetic energy is reported only, not checked against a candidate
  — a real gap the design doc did not anticipate.
- The seeded SMC MGQ/MGP catalog data uses each row's own minimum
  populated stroke as a single representative figure, not the full
  per-stroke table SMC actually publishes.

## Unsupported Conditions

- Dual-rod, table-cylinder, and rodless variants — each is a separate,
  later module (design doc "Out of Scope").
- Any load case (`normal`/`peak`/`holding`/`emergency_stop`) semantics.
- Cushion kinetic energy checked against a candidate's own catalog rating.
- Allowable lateral load for MGP candidates (no discrete rating exists in
  MGP's own catalog).
- Per-axis (separate roll/pitch/yaw) pass/fail reporting — SMC's own data
  supports only a combined check.
- A worked buckling example, or the buckling formula's own independent-
  benchmark comparison (same carried-forward gap as
  `pneumatic-cylinder-sizing@0.1.0`).
- SMC series other than MGQ/MGP.
- A self-serve catalog CSV upload UI.
- Rod-bearing wear, seal life, or a full fatigue/duty-cycle life
  calculation.
