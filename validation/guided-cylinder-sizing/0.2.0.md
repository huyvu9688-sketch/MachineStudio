# Module Validation Record — `guided-cylinder-sizing` 0.2.0

Completed against `validation/module-validation-template.md` (Unit 0.5).
This record documents Stage 4 (Validation) and Stage 6 (Release) of the New
Module Workflow (`context/ai-workflow-rules.md`) for `guided-cylinder-
sizing` 0.2.0 — Unit 7.3, Milestone 7 ("Common Automation Modules", roadmap
Phase 2). `0.2.0` is a new, additive version alongside the released,
immutable `0.1.0` (MGQ/MGP roll-pitch-yaw force/moment sizing) — a
simplified, MGP-first application-case selector that factors an
engineer-entered load mass once and defers every bore/bearing decision to
SMC's own published MGP selection graphs at the catalog-matching boundary,
per `docs/superpowers/plans/
2026-08-27-guided-cylinder-sizing-mgp-selection-implementation.md`.

**The reference-example item is met.** SMC's own two published MGP page-545
"Selection Example" scenarios (vertical mounting, horizontal mounting) are
reproduced end to end — through this module's own real compute path
(`executeModule`) and the real MGP catalog matcher
(`evaluateMgpGuidedCylinderCandidates`) — and each one selects the exact
model SMC's own text names as the answer (`MGPL25-30Z`, `MGPM20-30Z`), not
merely a passing candidate. **The independent-benchmark item is satisfied by
construction, not a second external source**: the module's own one
calculation (`m_design = m_entered × S_guided`) is direct-hand-check
arithmetic with nothing to independently benchmark; the real engineering
content — the MGP selection graphs themselves — is validated by digitizing
every labelled graph endpoint directly from SMC's own primary-source catalog
text (`lib/application/catalogs/mgp-selection-curves.ts`, 36 tests) and by
reproducing both worked scenarios' own stated model numbers, not by a
second manufacturer's competing method (no second guided-cylinder-graph
manufacturer method was found).

**A real, disclosed engineering finding, not a defect:** this module has no
bearing-type input port (`validityEnvelopeSummary`: "MGP graph selection ...
performed only by the catalog boundary"), so when a candidate list carries
both bearing types, the matcher's own ascending-bore ranking rule selects
`MGPM20-30Z` (slide, bore 20) for the *exact same inputs* as SMC's own
"Selection Example 1," not `MGPL25-30Z` — because SMC's own worked example
treats "Bearing type: Ball bushing" as a *given precondition* the engineer
already chose before consulting the graph, while this module's matcher
optimizes across every bearing type it is offered. Confirmed directly: bore
20's own slide-bearing graph-1 curve genuinely clears 3 kg at 90 mm
eccentric distance (~4.1 kg allowable). See "Tolerances and Deviations" and
`lib/application/catalogs/mgp-guided-cylinder-smc-examples.ts`'s own header
for the full account.

## Purpose and Supported Applications

Given an application case (vertical lifter, horizontal pusher, or stopper),
a load mass, an engineer-selected guided-load safety factor, a required
stroke, and operating pressure — plus, depending on the case, piston speed
and eccentric distance (lifter/pusher) or transfer speed (stopper) — this
module computes one factored graph-demand mass
(`m_design = m_entered × S_guided`) and preserves the common selection
context (case, stroke, pressure) for catalog matching. All graph selection,
candidate acceptance, and ranking happen at the catalog boundary
(`lib/application/catalogs/mgp-guided-cylinder-matching.ts`), which reads
the piston-speed/eccentric-distance/transfer-speed values directly from the
run's own input snapshot (`load-component-assignment-view.ts`'s dispatcher
passes `run.snapshot.input`, not just `run.snapshot.computation`, since this
module intentionally never echoes those selection-only values as outputs).
See `context/modules/guided-cylinder-sizing/0.2.0-stage-1-spec.md`
"Purpose".

## Validity Envelope and Assumptions

- One application case per run — not a comparison across all three at once.
- No force, moment, roll/pitch/yaw, friction, process-force, lateral-load,
  rotational-torque, or Euler-buckling calculation — a deliberate scope cut
  from `0.1.0`'s own MGQ/MGP roll-pitch-yaw sizing (`0.1.0` stays released,
  registered, and untouched; `0.2.0` does not replace it, both remain
  selectable module versions).
- `load_safety_factor` is a required input with no built-in default,
  minimum `1` (registry range) — the same "required input, no table
  adopted" treatment other modules in this project give a value no single
  manufacturer source publishes.
- Vertical-lifter and horizontal-pusher runs require piston speed and
  eccentric distance; stopper runs require transfer speed — enforced at
  `executeModule` (`package.test.ts`'s own boundary tests).
- **No bearing-type input port.** The matcher ranks every offered candidate
  by ascending bore, independent of bearing type — see this record's own
  header and "Tolerances and Deviations" for the real, disclosed
  consequence.
- **Stopper duty applies to MGPM (slide) candidates only** — MGPL/MGPA are
  physically excluded (MGP.md's own page-551 caution: "The MGPL (Ball
  bushing) and the MGPA (High precision ball bushing) cannot be used as a
  stopper"), enforced by the matcher (`mgp-guided-cylinder-matching.ts`'s
  own `applicationCase === "stopper" && bearingType !== "slide"` rejection).
- The page-552 stopper plots assume `L ≈ 50 mm`; for a longer `L`, SMC's own
  text says to select a sufficiently large bore — surfaced as a matcher
  warning (`MGP_STOPPER_SCOPE_WARNINGS`), not enforced as a hard limit
  (no numeric `L` input exists for stopper duty in SMC's own published
  method).
- No eccentric-distance selection-software envelope is digitized — a
  candidate whose eccentric distance falls outside every seeded graph's own
  labelled range is rejected with an honest "graph envelope does not cover"
  reason, never extrapolated.
- The seeded MGP-only catalog (`reference/catalog-seed/smc-mgp.csv`, one row
  per real basic MGP-Z model at one exact standard stroke, drawn from MGP
  catalogue page 203 / PDF printed page 537) is for the founder to review
  and trim — not a claim that every row is a part the founder stocks.

## Reference Examples (Published Worked Examples)

### Example 1 — MGP page-545 "Selection Example 1 (Vertical Mounting)"

- Source: `jp.smc.mgp_series_catalog@web-2026-08-26`, page 545
- Inputs: ball bushing, 30 stroke, 200 mm/s, 3 kg load mass, 90 mm eccentric
  distance, `load_safety_factor: 1` (isolates the catalog's own published
  condition — this module's own added multiplier has no catalog
  equivalent) (`mgp-guided-cylinder-smc-examples.ts`,
  `runMgpVerticalLifterExample`)
- MachineStudio result: `factored_load_mass = 3 kg`; the matcher selects
  graph 5 and accepts `MGPL25-30Z` as its top-ranked candidate (real
  published allowable mass at 90 mm ≈ 3.6 kg, interpolated log-log between
  the graph's own printed 26.2 mm/12.3 kg and 200 mm/1.63 kg points),
  rejecting the next-smallest ball-bushing bore `MGPL20-30Z` (real allowable
  ≈ 2.3 kg, below the 3 kg requirement) — the exact model SMC's own text
  names: "MGPL25-30Z is selected."
- Tolerance applied and why: exact for `factored_load_mass` (pure
  arithmetic); the graph-curve allowable-mass figures are this project's own
  log-log interpolation between SMC's own printed anchor points, not
  independently re-derived by hand for this record — validated instead by
  `mgp-selection-curves.test.ts`'s own boundary/anchor-point tests (36
  tests) and by this example's own model-selection outcome matching SMC's
  stated answer
- Pass / fail against tolerance: **pass**

### Example 2 — MGP page-545 "Selection Example 2 (Horizontal Mounting)"

- Source: `jp.smc.mgp_series_catalog@web-2026-08-26`, page 545
- Inputs: slide bearing, 50 mm plate-to-load-centre-of-gravity distance,
  200 mm/s, 2 kg load mass, 30 stroke, `load_safety_factor: 1`
  (`runMgpHorizontalPusherExample`)
- MachineStudio result: `factored_load_mass = 2 kg`; the matcher selects
  graph 13 and accepts `MGPM20-30Z` (real published allowable mass at
  30 mm stroke = 2.47 kg, an exact printed anchor point, no interpolation),
  rejecting the next-smallest slide bore `MGPM16-30Z` (real allowable =
  1.37 kg, below the 2 kg requirement) — the exact model SMC's own text
  names: "MGPM20-30Z is selected."
- Tolerance applied and why: exact (both the factored mass and the
  allowable-mass figure are exact, not interpolated)
- Pass / fail against tolerance: **pass**

## Tolerances and Deviations

- **Cross-bearing-type ranking is a real, disclosed behavior difference
  from a literal reading of SMC's own worked examples**, not a defect: SMC's
  own "Selection conditions" state bearing type as a given precondition
  (the same status "Stroke: 30 stroke" has), but this module has no
  bearing-type input port, so a candidate list spanning both bearing types
  ranks by ascending bore alone. Confirmed directly
  (`mgp-guided-cylinder-smc-examples.test.ts`,
  "MGP vertical lifter across BOTH bearing types"): offering both bearing
  types for Example 1's exact inputs selects `MGPM20-30Z` (bore 20), not
  `MGPL25-30Z` — bore 20's own slide-bearing graph-1 curve genuinely clears
  the requirement (~4.1 kg allowable at 90 mm, above the 3 kg factored
  load). `MGPL25-30Z` is still accepted, just ranked behind the smaller
  bore. A future bearing-type preference input, or founder-side candidate
  curation, would resolve this; out of `0.2.0`'s own scope.
- No numeric `L` input exists for stopper duty (SMC's own method gives none)
  — the `L ≈ 50 mm` assumption is surfaced as a warning, not enforced.
- No eccentric-distance selection-software envelope is digitized; a
  candidate outside every seeded graph's labelled range is rejected with an
  honest reason, never extrapolated.
- The seeded MGP-Z catalog data is one exact standard stroke per row, not a
  range — real, not synthetic, but a founder review/trim of the full
  representative set is still pending (same posture as every prior
  catalog-seed release in this project).

## Unsupported Conditions

- Any force, moment, roll/pitch/yaw, friction, process-force, lateral-load,
  rotational-torque, or Euler-buckling calculation — see `0.1.0` for that
  workflow, unchanged and still selectable.
- A bearing-type preference input (see "Tolerances and Deviations").
- A numeric `L` (plate-to-load-centre-of-gravity distance) input or check
  for stopper duty.
- Any load case (`normal`/`peak`/`holding`/`emergency_stop`) semantics.
- SMC series other than MGP.
- A self-serve catalog CSV upload UI.
- Rod-bearing wear, seal life, or a full fatigue/duty-cycle life
  calculation.
