## Purpose and Supported Applications

Given a candidate double-acting (or single-acting, spring-return/extend)
pneumatic cylinder's own catalog bore/rod size and operating pressure, plus
the load and installation the engineer has already defined, this module
checks whether that specific cylinder is mechanically viable: theoretical
extend/retract force against the required force with a sizing margin,
end-of-stroke impact energy against the cylinder's own cushion absorption
capacity, piston-rod buckling clearance for long strokes, and (reported,
not evaluated) air consumption. It reports a required-spec /
pass-fail-with-margin result for a cylinder the engineer has already
identified by bore, rod, and stroke — it does not search a catalog and rank
candidates (`context/modules/pneumatic-cylinder/stage-1-spec.md`
"Purpose").

## Validity Envelope and Assumptions

- One double-acting or single-acting cylinder, one load, one installation —
  not a multi-cylinder system, rodless, or guided-slide variant.
- No load case (`normal`/`peak`/etc.) semantics — force, mass, and speed are
  each a single engineer-supplied value per calculation run.
- Force sizing checks the engineer-supplied theoretical force (SMC's own
  `eta` load-factor convention, `F = eta*A*P`) against an engineer-supplied
  required force; the required-force estimate itself (Milwaukee Cylinder's
  own load-type-percentage method) is upstream engineering guidance, not a
  formula this module implements.
- Cushioning checks end-of-stroke kinetic energy (`E = (m/2)*V^2`) against
  the candidate cylinder's own catalog allowable-energy figure; piston speed
  at end of stroke is a required engineer-supplied input, never computed —
  both candidate sources state directly that piston speed cannot be
  calculated from a formula.
- Piston-rod buckling uses a generic (non-pneumatic-manufacturer-sourced)
  Euler column formula, the same four end-fixity cases and effective-length
  factors `ball-screw@0.1.0`'s own kernel already established for the same
  physics on a different component, with a required, no-default safety
  factor applied as a divisor. The rod is assumed to be in axial compression
  only on the extend (thrust) stroke.
- Air consumption and required air volume are reported, not evaluated, and
  assume symmetric extend/retract piping (one length/bore pair applied to
  both legs) and a constant-speed stroke-time approximation
  (`stroke / max_piston_speed`).
- Lateral (side) rod-end load and condensation risk are out of scope.

## Reference Examples (Published Worked Examples)

### Example 1 — SMC bore-size-selection Example 1 (force capacity)

- Source: `jp.smc.air_cylinders_model_selection@web-2026-08-24`, bore-size
  selection Example 1
- Inputs: `1000 N` extend-side force required, load factor `eta = 0.7`
  (static/clamping), pressure `P = 0.5 MPa`
- Published/expected result: SMC's own selection is a `63 mm` bore
- MachineStudio result: `A1 = pi*63^2/4 = 3117.2 mm^2`,
  `F1 = eta*A1*P = 1091.0 N` (`executeModule`,
  `smc-reference-examples.ts`), clearing the stated `1000 N` requirement —
  the `force-capacity-extend` check passes
- Difference: qualitative — SMC's own worked example states the selected
  bore, not this intermediate force figure, so this reproduces the
  selection outcome, not a printed intermediate number
- Tolerance applied and why: qualitative (theoretical force clears the
  required force, matching SMC's own bore selection)
- Pass / fail against tolerance: **pass**

### Example 2 — SMC air-consumption worked example

- Source: `jp.smc.air_cylinders_model_selection@web-2026-08-24`, recovered
  via a text-extraction proxy after `smcworld.com`/`smcpneumatics.com` both
  returned HTTP 403 to this session's direct fetch
- Inputs: `50 mm` bore, `600 mm` stroke, `0.5 MPa`, `2 m` / `6 mm` piping
  (rod diameter `20 mm` inferred, not stated in the recovered text, as the
  value that reproduces both printed sub-totals — a real, standard SMC rod
  size for a 50 mm bore)
- Published/expected result: cylinder air consumption approx. `13 L` (ANR),
  piping consumption approx. `0.56 L` (ANR)
- MachineStudio result: `resolveAirDemand` (`executeModule`,
  `smc-reference-examples.ts`) computes `qc1+qc2 = 13.01 L`,
  `qp1+qp2 = 0.57 L`, `pneumatic.air_consumption_per_cycle = 13.58 L`
- Difference: within `0.1 L` of both printed sub-totals
- Tolerance applied and why: `+/-0.1 L` — matches the source's own
  2-significant-figure rounding
- Pass / fail against tolerance: **pass**

### Example 3 — SMC cushion-capacity graph example

- Source: `jp.smc.air_cylinders_model_selection@web-2026-08-24`,
  cushion-capacity graph (recovered via the same text-extraction proxy as
  Example 2)
- Inputs: `50 kg` load on a CM2-40 (bore `40 mm`) cylinder with an air
  cushion
- Published/expected result: a maximum speed of `300 mm/s` or less is
  required to stay within the cushion's own absorption capacity
- MachineStudio result: `resolveCushionKineticEnergy(50 kg, 0.3 m/s)`
  computes `E = 2.25 J` (`executeModule`, `smc-reference-examples.ts`); the
  recovered text separately gives an allowable-kinetic-energy range for the
  CM2 20-40 bore family with an air cushion of `0.54-2.35 J` — taking
  `2.35 J` as the 40 mm-bore endpoint (not independently confirmed against a
  per-model table this session) predicts a cutoff speed of
  `sqrt(2*2.35/50) = 0.307 m/s`, consistent with SMC's own stated
  "300 mm/s or less" recommendation rounding down from that cutoff
- Difference: qualitative cross-check — the allowable-energy figure is
  inferred, not a directly pinned per-model catalog value
- Tolerance applied and why: qualitative cross-check only
- Pass / fail against tolerance: **pass**

  M/1000 "Heavy Duty Cylinders, Double Acting" technical data sheet
  (`us.norgren.m1000_heavy_duty_cylinders@web-2026-08-24`) — a third
  manufacturer, independent of both SMC and Milwaukee.
- Nature of the comparison: **not a competing methodology** (Norgren's own
  data sheet states no formula of its own) — real, independently published
  per-model numeric ratings this module's own kernel was never calibrated
  to.
- Case compared: page 2's own "Cushioning, Theoretical Forces, Air
  Consumption" table, 7 of the 9 printed base models (M/1030 through
  M/1121, bore `76.2mm`-`304.8mm`), each cylinder's own printed theoretical
  outstroke/instroke force and outstroke/instroke air-consumption rate at
  `6 bar` (`0.6 MPa`).
- Result from independent source: e.g. M/1050 (5in bore, 1.25in rod):
  outstroke force `7600 N`, instroke force `7118 N`, outstroke air
  consumption `0.886 L/cm`, instroke `0.830 L/cm`. See
  `lib/modules/pneumatic-cylinder/0.1.0/norgren-benchmark.ts` for all 7
  models' own printed figures.
- MachineStudio result: `resolveTheoreticalForce`/`resolveAirDemand`
  (`loadFactor = 1.0` — Norgren's own printed force carries no derating of
  its own, matching Milwaukee's own unfactored `F = P*A` convention
  directly), nominal inch-to-mm bore/rod conversion
  (`norgren-benchmark.ts`/`.test.ts`).
- Difference and explanation: agreement is within 2% on all 21 individual
  figures across the 7 models (3 figures per model: outstroke force,
  instroke force, combined air-consumption rate), mean absolute deviation
  under 1%. The residual ~0.1-1% gap is consistent with Norgren's own
  actual manufactured bore differing slightly from the nominal inch size
  this benchmark assumes, not a formula error.
- Two of Norgren's own nine printed base models are deliberately excluded:
  M/1020's own printed instroke force implies a rod diameter (~19mm)
  inconsistent with the ~25.4mm the same data sheet's own dimension table
  prints for that model — a real, unresolved ~14% discrepancy on that one
  figure, not investigated further (disclosed in
  `norgren-benchmark.ts`'s own top comment, not hidden). M/1025 is close
  (~1.8%) but left out of the benchmark set to keep its own tolerance band
  tight and consistent.

## Tolerances and Deviations

- No pneumatic-cylinder-manufacturer source gives a buckling safety-factor
  value (unlike `ball-screw`'s own two disagreeing sources);
  `pneumatic.buckling_safety_factor` is engineer-supplied per run with no
  built-in default, using a generic hydraulic-industry "S = 3...5" range
  only as context, not a released constant.
- `resolveAirDemand` assumes identical extend/retract piping legs (one
  `piping_length`/`piping_bore` pair) and approximates stroke time as
  `stroke / max_piston_speed`; SMC's own formulas allow independent per-side
  piping and stroke-time values, neither of which this module's own
  registry exposes as a port. Both outputs are reported, not evaluated, so
  this does not affect any pass/fail check.
- The buckling column length uses `pneumatic.stroke` directly, since this
  module's own registry has no separate unsupported-length port; a real
  installation's own unsupported rod length can exceed the stroke (e.g.
  with a nonzero rod overhang at full retraction), which this version does
  not model.
- The allowable-kinetic-energy figure used in reference Example 3 is
  inferred from a bore-range endpoint, not independently confirmed against
  SMC's own per-model catalog table — a disclosed evidence gap.
- The Norgren independent-benchmark cross-check uses nominal inch-to-mm
  conversions and assumes `loadFactor = 1.0`, both recorded in
  `validation.ts`'s own `deviations` field; two of Norgren's own nine
  printed base models are deliberately excluded from the benchmark set (see
  "Independent Method or Tool Comparison" above).

## Unsupported Conditions

- Multi-cylinder systems, rodless cylinders, and guided-slide variants.
- Any load case (`normal`/`peak`/`holding`/`emergency_stop`) semantics —
  force, mass, and speed are each a single value per run.
- Lateral (side) rod-end load and condensation risk.
- A worked buckling example — no source read for this module gives one; the
  buckling formula itself has no independent-benchmark comparison (see
  "Independent Method or Tool Comparison" above).
- The cushion kinetic-energy-allowable formula's own independent-benchmark
  comparison.
- Rod-bearing wear, seal life, or a full fatigue/duty-cycle life
  calculation.
