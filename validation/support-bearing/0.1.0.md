## Purpose and Supported Applications

Given a candidate ball-screw shaft support bearing's own catalog rating
data (basic dynamic load rating, basic static load rating, allowable
rotational speed, dynamic/static equivalent-load factors, bore/outside
diameter, preload) plus the axial thrust force and rotational speed already
resolved by `axis-load-cases` (Unit 4.1) and `ball-screw` (Unit 4.3), this
module checks whether that specific support bearing is mechanically viable
for the axis: basic (L10) rating life under the applied load, static safety
factor, and allowable-speed margin. It reports a required-spec /
pass-fail-with-margin result for a support bearing the engineer has already
identified by model — it does not search a catalog and rank candidates
(`context/modules/support-bearing/stage-1-spec.md` "Purpose"). It models
one support bearing per calculation run: `bearing.location` selects
`fixed` (the angular-contact bearing that reacts axial thrust) or
`supported` (the floating deep-groove bearing that does not).

## Validity Envelope and Assumptions

- One support bearing per calculation run (`bearing.location` selects
  `fixed` or `supported`) — not a combined fixed+floating calculation.
- Only the `normal` and `peak` load cases, matching `axis-load-cases
  0.1.0`'s and `ball-screw 0.1.0`'s own scope restriction.
- Two-point shaft support only (matching `screw.end_support_arrangement`'s
  own four values, all two-point); NTN's own three-point reaction formulas
  are sourced but not implemented.
- Ball bearings only (life exponent `p = 3`); a roller-type or tapered-
  roller support bearing is out of scope.
- Axial load (fixed-side only) reuses `motion.axis.thrust_force` directly —
  the same load `ball-screw`'s own kernel already resists internally,
  satisfying the roadmap's own Unit 4.6 gate ("integrates with the ball
  screw module without a custom link mapping").
- Radial load has no clean upstream source and is a new required
  engineer-supplied input, `bearing.actual_radial_load`.
- The dynamic/static equivalent-load factors (`X`, `Y`, `X0`, `Y0`) are
  engineer-supplied catalog lookups, not a reproduced universal table — no
  source read gives one (NTN's own handbook states they are printed in
  "the dimensions table of the catalog," i.e. bearing-model-specific).
- `bearing.static_safety_factor_minimum` is a required input with no
  built-in default, even though only one source's own numbers (NTN
  Table 6.4) were read — extending every other module's own precedent even
  where no second source exists to disagree with the first.
- `bearing.bore_diameter`, `bearing.outside_diameter`, and
  `bearing.preload` are reported catalog values only, not evaluated against
  an actual shaft/housing diameter.
- NTN's own speed correction factors (`fL`, `fC`) are not implemented — the
  catalog allowable speed is used uncorrected.
- A case with exactly zero dynamic/static equivalent load or exactly zero
  operating speed is unsupported: `compute` throws rather than reporting an
  infinite life or safety factor.
- No torsional-resonance check, no 3-point statically-indeterminate load
  derivation, no fit-tolerance-class (h6/k5/js5) verification.

## Sources and Methods Used

| Source revision | Classification | Used for |
| --- | --- | --- |
| `jp.thk.ball_screw_general_catalog@technico-mirror-2026-08-09` | `manufacturer_method` | Support-unit physical structure and per-model catalog/data-sheet values (fixed-side angular contact bearing, supported-side deep-groove bearing) — no life or safety-factor formula of its own. |
| `jp.ntn.rolling_bearings_handbook@cat-9012e` | `manufacturer_method` | Primary formula source: dynamic equivalent load and basic rating life (`P = X*Fr + Y*Fa`; `L10 = (C/P)^3 * 10^6`; `L10h = L10/(60n)`), static equivalent load and static safety factor (`P0 = max(X0*Fr + Y0*Fa, Fr)`; `S0 = C0/P0`), Table 6.4 static-safety-factor lower-limit reference values. Its own "Bearing Life Calculation Examples" section (printed page 84) is missing from three independently-fetched editions — a documented gap this module's own reference examples do not rely on NTN to close (see `jp.nsk.rolling_bearings_catalog` below). |
| `jp.nsk.rolling_bearings_catalog@e1102a-2005` | `manufacturer_method` | Both Stage 4 evidence items: Section 5.7's own worked Examples 1 and 3 (reference examples below) and Table 5.2's own `fh`/`fn` fatigue-life-factor method (independent benchmark below). |

None of the three sources is a consensus standard: NTN's and NSK's own
methods restate the ISO 281 "catalogue method" for rolling-bearing basic
rating life without citing ISO 281 directly, so this project cites their
own restatements, not the standard itself.

## Reference Examples (Published Worked Examples)

Both worked examples come from one source (NSK's own catalog); each is
itemized into its two independently-tested checkpoints (dynamic equivalent
load, then nominal life), the same granularity `linear-guide`'s own PMI
Chapter 9 example uses when one published scenario supports multiple
distinct formula checks.

### Example 1 — NSK Example 1, dynamic equivalent load (pure radial)

- Source: `jp.nsk.rolling_bearings_catalog@e1102a-2005`, "Rolling Bearings"
  (CAT. No. E1102a) Section 5.7, Example 1, printed page A34
- Inputs: single-row deep-groove ball bearing 6208, `Fr = 2500 N`,
  `n = 900 rpm`, `Cr = 29,100 N`, pure radial load (`X = 1`, no axial
  component)
- Published/expected result: `P = Fr = 2500 N` ("Since only a radial load
  is applied")
- MachineStudio result: reproduced through `executeModule` as a
  `bearing.location = "supported"` run
  (`lib/modules/support-bearing/0.1.0/nsk-reference-examples.ts`)
- Difference: none — exact match
- Tolerance applied and why: floating-point precision — the reduction to
  `P = Fr` is an exact arithmetic identity, not a rounded figure
- Pass / fail against tolerance: **pass**

### Example 2 — NSK Example 1, nominal life

- Source: same as Example 1
- Inputs: same as Example 1
- Published/expected result: "approximately 29,000 hours of service life"
  (`fh = 3.88`, read from NSK's own Fig. 5.4 chart)
- MachineStudio result: `bearing.nominal_life_hours` from the same
  `executeModule` run, converted to hours
- Difference: within NSK's own 2-3-significant-figure statement
- Tolerance applied and why: `2%` relative — a documented allowance for
  NSK's own chart-reading rounding (`fh` is read from a chart, not computed
  to full precision), not slack introduced to pass the test
- Pass / fail against tolerance: **pass**

### Example 3 — NSK Example 3, dynamic equivalent load (radial + axial)

- Source: `jp.nsk.rolling_bearings_catalog@e1102a-2005`, Section 5.7,
  Example 3, printed page A34
- Inputs: the same bearing 6208 and radial load as Example 1, plus an axial
  load `Fa = 1000 N`, NSK's own printed factors `X = 0.56`, `Y = 1.67`
- Published/expected result: `P = 0.56*2500 + 1.67*1000 = 3070 N`
- MachineStudio result: reproduced through `executeModule` as a
  `bearing.location = "fixed"` run
- Difference: none — exact match
- Tolerance applied and why: floating-point precision
- Pass / fail against tolerance: **pass**

### Example 4 — NSK Example 3, nominal life

- Source: same as Example 3
- Inputs: same as Example 3
- Published/expected result: "approximately 15,800 hours" for ball
  bearings (`fh = 3.16`)
- MachineStudio result: `bearing.nominal_life_hours` from the same
  `executeModule` run, converted to hours
- Difference: within NSK's own 2-3-significant-figure statement
- Tolerance applied and why: `2%` relative, the same chart-reading
  allowance as Example 2
- Pass / fail against tolerance: **pass**

All four examples share one additional confirmation:
`nsk-reference-examples.test.ts` also asserts the module's own trace
resolves an operating speed of exactly `900 rpm` from the derived linear
velocity and lead — both examples' own `lead`/`linear_velocity` inputs are
chosen only to reproduce NSK's own printed `n = 900 rpm` exactly, since NSK
states rotational speed directly rather than a linear velocity.

Ports outside what NSK's own text specifies (allowable speed, the
static-load-factor pair, bore/outside diameter, the static-safety-factor
minimum, and the entire `peak` case) are not sourced from NSK — they are
set to comfortably-passing placeholder values so the full required port set
is satisfied without affecting the dynamic-equivalent-load or
nominal-life-hours figures under test (`nsk-reference-examples.ts`'s own
module doc comment records exactly which).

## Independent Method or Tool Comparison

**Satisfied (2026-08-10).**
`lib/modules/support-bearing/0.1.0/nsk-fh-benchmark.ts` implements NSK's
own distinct "fatigue life factor" (`fh`) / "speed factor" (`fn`) method as
a genuine second computation — the roadmap's Definition of Done item 9.

- Independent method/tool: NSK Ltd., "Rolling Bearings" (CAT. No. E1102a),
  Table 5.2 (ball-bearing column): `fn = (0.03n)^(-1/3)`, `fh = fn*C/P`,
  `Lh = 500*fh^3`
- Case(s) compared: the same NSK Example 1 and Example 3 the reference
  examples above use
- Result from independent method: `fh = 3.88` (Example 1), `fh = 3.16`
  (Example 3), reproducing NSK's own stated `~29,000 h` / `~15,800 h`
- MachineStudio result: `nsk-fh-benchmark.ts`'s own `fh`/`Lh` computation
  matches NSK's own figures to the same tolerance as the reference examples
  above
- Difference and explanation: none unexplained. The two methods are then
  shown to be a proved algebraic identity, not merely a numeric
  coincidence: substituting NSK's own `fn` formula into `Lh = 500*fh^3`
  reduces exactly to `(C/P)^3 * 10^6/(60n)`, the same form `math.ts`'s own
  `resolveNominalLife`/`resolveLifeHours` already computes (derivation in
  `nsk-fh-benchmark.ts`'s own module doc comment) — `nsk-fh-benchmark.test.ts`
  asserts the two agree to floating-point precision across four cases, the
  same "two independently-sourced formulations of one physics, proved
  identical" treatment `lib/modules/linear-guide/0.1.0/iko-benchmark.ts`
  gives PMI's and IKO's own equivalent-load forms.

NSK's own two short "Technical Insight" bulletins (`TI Bearing Life.pdf`,
`P_TI-0102_EN.pdf`), read in an earlier session, had already corroborated
the same formula shape without a full worked example to reproduce; this
benchmark closes that gap with NSK's own full catalog instead.

## Tolerances and Deviations

- NTN's own speed correction factors `fL`/`fC` (handbook Ch. 10,
  Figs. 10.1-10.2) are printed only as graphs, not closed-form equations,
  and are not implemented — the catalog allowable speed is used
  uncorrected (`math.ts`'s own module doc comment).
- `bearing.bore_diameter` and `bearing.outside_diameter` are reported, not
  evaluated — a real scope narrowing from `stage-1-spec.md`'s own initial
  "simple bound check" proposal, since a support bearing's bore is
  manufactured to one matched shaft diameter, not a clamping range the way
  `coupling.driving_bore_min`/`max` is.
- Whether NTN's own "basic static load rating" (`C0`) and THK's own
  "static permissible load" figure for its fixed-side support-unit bearing
  are the same quantity under different table headings is not resolved —
  `stage-1-spec.md` "Evidence Gaps" records this as needing direct
  confirmation against THK's own terminology-definition pages; `0.1.0`
  treats an engineer-supplied `bearing.static_load_rating` as the
  authoritative figure regardless of which catalog table it was read from.
- No second source's own numbers exist to corroborate NTN's Table 6.4
  static-safety-factor lower-limit values — `bearing.static_safety_factor_
  minimum` is required with no built-in default anyway, the same treatment
  every other module's own un-corroborated safety-factor minimum receives.

## Unsupported Conditions

- `holding` and `emergency_stop` load cases — only `normal` and `peak` are
  resolved.
- A combined fixed+floating calculation in one run — the engineer runs this
  module once per bearing location.
- Three-or-more-point (statically-indeterminate) shaft support — NTN's own
  Table 7.3 reaction formulas are sourced but not implemented.
- Roller-type or tapered-roller support bearings — ball bearings only.
- NTN's own speed correction factors `fL`/`fC` — the catalog allowable
  speed is used uncorrected.
- Bore/outside-diameter and preload checks against an actual shaft/housing
  — these are reported catalog values only.
- Torsional-resonance or periodic-vibration checks — no released
  motor/load-inertia parameter exists yet.
- A case with exactly zero dynamic/static equivalent load or exactly zero
  operating speed — `compute` throws rather than reporting an infinite
  life or safety factor.
