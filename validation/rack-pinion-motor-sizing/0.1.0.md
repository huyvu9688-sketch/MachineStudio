## Purpose and Supported Applications

Given a rack-and-pinion linear axis's own pinion geometry and mass, total
moving mass, friction, orientation, and one commanded accelerate-to-speed
motion event, computes the required motor specifications a motor for that
axis must meet: load torque, acceleration torque, maximum momentary
torque, required torque with an engineer-supplied safety factor, operating
speed, required power, total reflected system inertia, and inertia ratio.
Reports required-spec values and pass/fail checks against
engineer-supplied margins, the same scope both prior Motor Sizing Tool
modules already established. Does not check rack/pinion gear-tooth
mechanical strength, select a gearbox/coupling/drive/brake, or match a
motor catalog (ADR-0011 "Output scope").

## Validity Envelope and Assumptions

- One rack-and-pinion linear axis: one pinion (rack treated as infinitely
  rigid/massless — no source found gives it a mass or inertia term), one
  rigid carriage/load, direct-connected or through a single fixed gear
  ratio.
- One accelerate-to-speed motion event — not a repeating duty cycle, no
  return/lowering move.
- Horizontal, vertical, or inclined orientation
  (`0 <= incline_angle <= 90 deg`). Validated end to end at exactly
  `theta=0` and `theta=90 deg`; no worked example at an intermediate
  incline angle was available from any source.
- Self-contained per ADR-0011 "Reuse policy": reproduces, rather than
  imports, Oriental Motor Co., Ltd.'s and Andantex USA, Inc.'s own
  rack-and-pinion sizing methods. The one genuine import is
  `lib/engine/mechanics` (Unit 6.1).
- No rack/pinion gear-tooth mechanical-strength check and no motor catalog
  matching.

## Independent Method or Tool Comparison

**Satisfied (2026-08-13), and doing double duty as this module's own
reference-example evidence.** `atlanta-benchmark.test.ts` reproduces both
of Atlanta Drive Systems' own worked numerical examples through the real
`executeModule` compute path.

- Independent method/tool: Atlanta Drive Systems' own tangential-force
  formula (`Fu = m*g*mu+m*a` horizontal, `Fu = m*g+m*a` vertical),
  reused directly from `axis-load-cases@0.1.0`'s own already-tested
  `resolveAtlantaHorizontalForce`/`resolveAtlantaVerticalForce`
  (`atlanta-benchmark.ts`, a cross-module test-only import — never part
  of this module's own shipped package)
- Case(s) compared: "travelling operation" (`m=820 kg`, `v=2 m/s`,
  `tb=1 s`, `mu=0.1`, Atlanta's own `g=9.81 m/s^2` — overridden explicitly
  in the test scenario to match exactly) and "lifting operation"
  (`m=300 kg`, `v=1.08 m/s`, `tb=0.27 s`)
- Result from independent method: `Fu=2444.42 N` (`2.44 kN` published) and
  `Fu=4143 N` (`4.1 kN` published), both reproducing
  `axis-load-cases@0.1.0`'s own already-tested figures exactly
- MachineStudio result: `momentary_torque` (`load_torque+
  acceleration_torque`), through `executeModule` with a negligible
  (`0.001 kg`) pinion mass, `gear_ratio=1`, `mechanical_efficiency=1`, and
  `external_force=0` (matching Atlanta's own scope, which has no
  efficiency derating or gearbox reduction), converted from Atlanta's own
  `Fu` via `Fu*D/2` for an arbitrarily chosen `D=0.1 m` (algebraically
  D-independent for this comparison, verified by hand)
- Difference and explanation: `< 0.01%` for both scenarios — the residual
  is the negligible pinion's own rotating inertia (absent from Atlanta's
  own force-only `Fu`, which has no pinion-inertia term at all)

The `Fu*D/2` conversion itself is independently justified, not invented
for this benchmark: Andantex USA, Inc.'s own separately published
`Tp=Fr*d/2` relationship (`stage-1-spec.md` "Candidate Methods" item 3)
states the identical force-to-torque conversion.

## Tolerances and Deviations

- Andantex USA, Inc.'s own `Tp=Fr*d/2` formula shows no explicit
  mechanical-efficiency divisor, unlike Oriental Motor's own
  `T_L=F*D/(2*eta*i)` — Andantex's own procedure instead compares the
  un-derated `Tp` against a catalog torque rating that presumably already
  accounts for mesh losses. This module's own kernel follows Oriental
  Motor's own explicit-efficiency form, consistent with every other Motor
  Sizing Tool module. A real, disclosed structural difference between the
  two corroborating public sources, not silently resolved.
- A genuine, disclosed arithmetic inconsistency was found (and is not
  reproduced) in Atlanta Drive Systems' own document while hand-verifying
  its "lifting operation" example: the printed `Fu_perm` calculation
  states `Futab=11.5 kN` in its own formula line but the preceding
  sentence states `Futab=12 kN`; neither value reproduces either of the
  document's own two different printed results (`5.9 kN`, `6.0 kN`)
  exactly. This figure is a hardware-selection derating check entirely out
  of this module's own scope regardless — recorded for completeness.

## Unsupported Conditions

- The rack's own mass or inertia — treated as infinitely rigid/massless.
- A repeating duty cycle or effective (RMS) torque check.
- Rack/pinion gear-tooth mechanical-strength checks (root bending
  fatigue, Hertzian pitting fatigue, permissible catalog load inertia) —
  a hardware-selection question, symmetric with `ball-screw@0.1.0`'s own
  separate responsibility.
- Motor catalog matching or part selection.
- Intermediate incline angles (`0 < theta < 90 deg`) — validated at
  exactly horizontal and vertical only.
- No `linear-axis@1` or other guided-workflow role — standalone in
  `0.1.0` (ADR-0011).
