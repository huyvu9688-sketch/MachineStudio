## Purpose and Supported Applications

Given a load (mass, incline angle, friction coefficient, optional
extend-stroke process force), a required stroke, and the engineer's own
operating pressure, force-sizing load factor, cushion type, mounting style,
and buckling safety factor, this module computes the required extend/retract
force and required cushion kinetic energy, then ranks real SMC CM2/CA2
catalog cylinder candidates against that requirement (theoretical force,
cushion capacity, stroke range, mounting style, and piston-rod buckling) via
`lib/application/catalogs/pneumatic-cylinder-matching.ts`. It is the
load-in/catalog-match-out counterpart to `pneumatic-cylinder@0.1.0`'s own
check-a-given-cylinder scope — the same "self-contained, no upstream module
link" precedent ADR-0011 established for the Motor Sizing Tool family,
applied to a different mechanism
(`context/modules/pneumatic-cylinder-sizing/stage-1-spec.md` "Purpose").

## Validity Envelope and Assumptions

- One load, one installation, one required stroke — not a multi-cylinder
  system, rodless, or guided-slide variant (same scope narrowing as
  `pneumatic-cylinder@0.1.0`).
- No load case (`normal`/`peak`/etc.) semantics — every input is a single
  engineer-supplied value per calculation run.
- Required-force resolution is general Newtonian statics (mass, standard
  gravity `9.80665 m/s^2`, incline, Coulomb friction), reproducing
  `ball-screw-motor-sizing@0.2.0`'s own forward/return sign convention:
  friction is direction-symmetric (always added, since it opposes motion
  either way); only the gravity term flips sign with direction.
  `required_retract_force` may be legitimately negative for a strongly
  gravity-assisted return stroke on a heavy unbalanced load — reported as
  computed, never clamped or `Math.abs()`-ed inside `compute()`. The
  catalog matcher floors it at 0 N only when building its own force-capacity
  criterion (a negative requirement is trivially satisfied by any
  candidate).
- Process force is applied on the extend (working) stroke only — a
  disclosed `0.1.0` simplification, matching `pneumatic-cylinder@0.1.0`'s
  own "buckling governs on the extend side" assumption.
- Force capacity, cushion kinetic energy, and buckling are evaluated
  per-candidate against a real catalog row using formulas reproduced
  independently from `pneumatic-cylinder@0.1.0`'s own kernel (not imported,
  per ADR-0011's reuse policy) — no new, unsourced "solve for minimum bore"
  inverse formula is invented.
- Piston-rod buckling uses the same generic (non-pneumatic-manufacturer-
  sourced) Euler column formula and four end-fixity cases
  `pneumatic-cylinder@0.1.0`'s own kernel already established, governing on
  the extend (thrust) stroke only.
- Catalog matching is a hybrid: the generic `rankCandidates`/`MatchCriterion`
  engine (`lib/catalog`) handles stroke range, mounting style, and cushion
  energy (true single-attribute comparisons); a dedicated application-layer
  evaluator handles force capacity and buckling, which need a real
  per-candidate formula over that candidate's own bore/rod diameter — the
  existing `MatchCriterion` contract cannot express that. Neither
  `lib/catalog`'s generic engine nor the `CatalogAdapter` SDK contract is
  changed by this module.
- The seeded SMC CM2/CA2 catalog (`reference/catalog-seed/smc-cm2-ca2.csv`,
  36 rows) is a representative dataset drawn from SMC's own published
  catalog dimensions, for the founder to review and trim to their real
  working set — not a claim that every row is a part the founder actually
  stocks or specifies. No self-serve catalog-upload UI exists; the seed
  import (`scripts/seed-pneumatic-cylinder-catalog.mts`) is a one-time
  operation using the existing generic CSV import pipeline.
- Lateral (side) rod-end load is out of scope, matching
  `pneumatic-cylinder@0.1.0` (no reproducible formula found, catalog graphs
  only).

## Reference Examples (Published Worked Examples)

### Example 1 — SMC bore-size-selection Example 1, reached via a load (not a directly-supplied force)

- Source: `jp.smc.air_cylinders_model_selection@web-2026-08-24`, bore-size
  selection Example 1 — the same scenario `pneumatic-cylinder@0.1.0`'s own
  validation record cites
- Inputs: a vertical lift (`incline_angle = 90 deg`), zero friction, zero
  process force, `load_mass = 1000 / 9.80665 kg` (reproduces the identical
  `1000 N` extend-side force requirement algebraically:
  `required_extend_force = load_mass * g * sin(90deg) = load_mass * g`),
  load factor `eta = 0.7` (static/clamping), pressure `P = 0.5 MPa`
- Published/expected result: SMC's own selection is a `63 mm` bore
- MachineStudio result: this module's own compute path
  (`smc-reference-example.ts`, `runSmcBoreSelectionExample`) resolves
  `required_extend_force = 1000.0 N`; the candidate `63 mm` bore (`20 mm`
  rod, a standard CM2-63 dimension) clears it at `F1 = eta*A1*P ~= 1091.0 N`
  through this module's own reproduced `resolvePistonAreas`/
  `resolveTheoreticalForce` — the same figure `pneumatic-cylinder@0.1.0`'s
  own validation record already confirms for this exact scenario
- Difference: qualitative — SMC's own worked example states the selected
  bore, not an intermediate force figure, so this reproduces the selection
  outcome, not a printed intermediate number
- Tolerance applied and why: qualitative (theoretical force clears the
  required force, matching SMC's own bore selection and
  `pneumatic-cylinder@0.1.0`'s own reference example for this scenario)
- Pass / fail against tolerance: **pass**

## Independent Method or Tool Comparison

**Satisfied by reference, not re-derived.** The theoretical-force,
cushion-kinetic-energy, and buckling formulas are reused/reproduced
unchanged from `pneumatic-cylinder@0.1.0`, which already has a completed
independent benchmark (Norgren M/1000, 7 bore sizes, agreement within 2% on
21 figures) for the theoretical-force formula area, and a disclosed,
carried-forward evidence gap for cushion-kinetic-energy-allowable and
buckling (no second independent source of any kind) — see
`validation/pneumatic-cylinder/0.1.0.md` "Independent Method or Tool
Comparison" for the full account (Norgren's own M/1000 data sheet, 7 of 9
printed base models, agreement within 2% on all 21 individual figures, mean
absolute deviation under 1%).

This record cites that prior work by reference rather than re-running it,
since the formulas themselves are byte-for-byte identical — confirmed
directly by this module's own `math.test.ts` reproducing
`pneumatic-cylinder@0.1.0`'s own `math.test.ts` fixtures through this
module's own `resolvePistonAreas`/`resolveTheoreticalForce`/
`resolveBucklingLoad`/`resolvePermissibleCompressiveLoad`.

The required-force resolution itself (new physics, general Newtonian
statics) is not covered by the Norgren benchmark and has no manufacturer
method to benchmark against — verified instead by the sign-convention
property tests in this module's own `math.test.ts` (adds gravity forward,
subtracts it on return, friction direction-symmetric, can go negative),
cross-checked against `ball-screw-motor-sizing@0.2.0`'s own established
`resolveDriveForce` convention.

### What this closes and what it does not

Carries forward `pneumatic-cylinder@0.1.0`'s own exact evidence-gap split:
closed for 2 of 4 formula areas (theoretical force, air consumption is not
applicable to this module — it has no air-consumption port); still open for
cushion-kinetic-energy-allowable and buckling — no second independent
source of any kind for either, an explicit, disclosed `0.1.0` limitation,
not silently resolved here.

## Tolerances and Deviations

- Reproduces every disclosed evidence gap `pneumatic-cylinder@0.1.0`
  already carries for the force/cushion/buckling formula areas (see that
  module's own `validation.ts` and `validation/pneumatic-cylinder/0.1.0.md`)
  — not silently resolved here.
- Process force is applied on the extend stroke only (see "Validity
  Envelope and Assumptions").
- The buckling column length uses `pneumatic_sizing.required_stroke`
  directly, the same "no separate unsupported-length port" simplification
  `pneumatic-cylinder@0.1.0`'s own validation record already discloses for
  its own `pneumatic.stroke`-based buckling check.
- The seeded SMC CM2/CA2 catalog data is representative, not a claim that
  every seeded row is a real stocked part — see "Validity Envelope and
  Assumptions" above and the module's own `stage-1-spec.md` "Task 13 fetch
  record" for the full disclosure of two real rod-diameter corrections
  found this session (CM2 bore 40 is 14 mm, not the assumed ISO 6431 16 mm;
  the shared bore-100 table is 30 mm, not 25 mm) and one inferred (not
  directly confirmed) value (CA2 bore-40 rod, 16 mm).
- The mounting-suffix model-number labels in the seed CSV
  (`-basic`/`-foot`/`-flange`/`-clevis`) are descriptive placeholders, not
  SMC's own real model-number suffix convention — Task 13's fetch did not
  confirm the real suffix letters SMC uses per mount type, so none is
  fabricated.

## Unsupported Conditions

- Multi-cylinder systems, rodless cylinders, and guided-slide variants.
- Any load case (`normal`/`peak`/`holding`/`emergency_stop`) semantics —
  every input is a single value per run.
- Lateral (side) rod-end load.
- A worked buckling example — no source read for this module or
  `pneumatic-cylinder@0.1.0` gives one; the buckling formula itself has no
  independent-benchmark comparison.
- The cushion kinetic-energy-allowable formula's own independent-benchmark
  comparison.
- SMC series other than CM2/CA2.
- A self-serve catalog CSV upload UI — the seed import is a one-time
  operation for this release.
- Rod-bearing wear, seal life, or a full fatigue/duty-cycle life
  calculation.
