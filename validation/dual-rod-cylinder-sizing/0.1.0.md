## Purpose and Supported Applications

Given a load (mass, incline angle, friction coefficient, optional
extend-stroke process force), a required stroke, an overhang length, and
the engineer's own operating pressure, force-sizing load factor, cushion
type, and mounting orientation (vertical/horizontal), this module computes
the required extend/retract force and required cushion kinetic energy,
then ranks real SMC CXS2 (CXS2M slide-bearing / CXS2L ball-bushing)
dual-rod catalog candidates against that requirement (theoretical force,
stroke range, and a load-mass-vs-overhang-length structural check unique
to this twin-guide-rod mechanism) via `lib/application/catalogs/
dual-rod-cylinder-matching.ts`. See `context/modules/
dual-rod-cylinder-sizing/stage-1-spec.md` "Purpose".

## Validity Envelope and Assumptions

- One load, one installation, one required stroke — not a multi-cylinder
  system, round-body, guided-cylinder, table-cylinder, or rodless variant
  (each is a separate module; design doc "Sequencing"/"Out of Scope").
- No load case (`normal`/`peak`/etc.) semantics — every input is a single
  engineer-supplied value per calculation run.
- Required-force resolution is identical to `pneumatic-cylinder-
  sizing@0.1.0`'s own forward/return sign convention, reproduced
  independently.
- **Theoretical force uses a doubled piston area, unique to this module.**
  CXS2 is a confirmed genuine dual-piston mechanism — not the plain
  single-piston formula every sibling pneumatic sizing module in this
  project uses. This was found and corrected mid-Stage-3/4 (2026-08-27):
  an earlier Stage 1 conclusion wrongly inferred "not doubled" by
  comparing CXS2's own Theoretical Output table only against the older
  CXSJ catalog's own table (CXSJ was itself already double-piston, so the
  match proved nothing about either matching a plain single-piston
  baseline). Corrected once SMC's own primary-source catalog text became
  directly available (`reference/source-material/dual-rod-cylinder/
  CXS2.md`), confirming the doubled area at two independent bore sizes
  (10mm, 32mm), both directions (4 independent data points). See
  `context/modules/dual-rod-cylinder-sizing/stage-1-spec.md` "CORRECTION
  (2026-08-27)".
- **No buckling check.** Unlike `pneumatic-cylinder-sizing@0.1.0` and
  `guided-cylinder-sizing@0.1.0`, this module has no Euler column buckling
  formula. SMC's own CXS2 catalog gives no buckling formula, and this
  mechanism's own governing structural check is SMC's own directly-
  published load-mass-vs-overhang-length rating instead — a disclosed
  scope difference, not a gap (`stage-1-spec.md` "No buckling check for
  this family").
- **Load-mass-vs-overhang-length band selection is a founder-directed
  engineering judgment call, not a rule SMC's own catalog states
  directly.** The module selects the narrowest seeded stroke/speed band
  covering the engineer's own real `required_stroke`/`max_piston_speed`,
  rounding up rather than gating on a fixed worst-case band — a
  founder correction (2026-08-26) that redirected an earlier plan (a
  single hidden worst-case margin) as systematically over-rejecting
  ordinary designs (`stage-2-contract.md` Decision 6).
- **Cushion kinetic energy is reported only, not checked against a
  candidate.** CXS2's own catalog gives no per-model allowable-kinetic-
  energy table this module has digitized — a disclosed 0.1.0 evidence gap.
- The digitized load-mass-vs-overhang dataset (130 curves: 44 vertical +
  86 horizontal, one per bore x bearing-type combination across SMC's own
  21 published graphs) is read by eye off founder-supplied graph images to
  2 significant figures — a real, disclosed accuracy ceiling distinct from
  a printed-table transcription. One row (graph 10, bore 6, CXS2L speed
  band) carries a disclosed, best-evidenced-reading resolution of a
  genuinely ambiguous source-table annotation, flagged for founder
  confirmation against the real graph image
  (`lib/modules/dual-rod-cylinder-sizing/0.1.0/load-mass-curves.ts`).
- The check reports out-of-envelope, never extrapolating, when the query
  falls outside every seeded band.
- The seeded SMC CXS2 catalog (`reference/catalog-seed/smc-cxs2.csv`, 12
  rows — 6 bores x 2 bearing types) uses real bore/rod/stroke-range
  dimensions confirmed directly from SMC's own catalog text, for the
  founder to review and trim to their real working set — not a claim that
  every row is a part the founder actually stocks.

## Independent Method or Tool Comparison

**The theoretical-force formula area is directly confirmed against SMC's
own primary-source catalog text, not merely cited by reference from a
sibling module's own benchmark.** `reference/source-material/
dual-rod-cylinder/CXS2.md`'s own "Theoretical Output" table gives printed
OUT/IN piston-area figures for CXS2m10 (rod 6mm: OUT 157mm², IN 100mm²)
and CXS2m32 (rod 16mm: OUT 1608mm², IN 1206mm²) — this module's own
`resolvePistonAreas` reproduces both to within 1% (`math.test.ts`'s own
`matches SMC's own published CXS2 Theoretical Output areas` tests), at
two independent bore sizes, in both directions (4 independent data
points). This is a same-manufacturer primary-source confirmation, not an
independent second manufacturer's method — it does not by itself satisfy
this project's own "independent method or tool" standard the way
IKO-vs-PMI or KTR-DIN-740-vs-KTR's-other-document did for other modules,
but it is a stronger evidence basis than a benchmark cited purely by
reference from a sibling module, since it directly re-derives the
formula's own governing constant (the dual-piston factor) from the
manufacturer's own printed data rather than assuming it transfers
unchanged.

**The load-mass-vs-overhang-length interpolation has no manufacturer
method to benchmark against.** SMC publishes this relationship only as
21 log-log graphs, digitized by this module's own dataset — no second
manufacturer's equivalent graph and no established general engineering
method exists for this exact twin-guide-rod-plate structural
relationship. Verified instead by property tests in `math.test.ts`
(the geometric-mean value at the true log-log midpoint of a curve's own
range, an independently-derivable property of log-log — not linear —
interpolation; the no-flat-plateau boundary case; rejection of a
corrupted matched-curve's own non-positive load-mass field) and by
data-integrity tests in `load-mass-curves.test.ts` (monotonic
non-increasing load mass vs. overhang across all 130 curves, no
duplicate band keys, strictly positive load-mass/overhang fields).

### What this closes and what it does not

Closes the theoretical-force formula area's own evidence basis more
directly than either sibling module achieved for their own single-piston
formula (a primary-source re-derivation of the governing area constant,
not a citation chain). The load-mass-vs-overhang-length formula area
remains without any independent benchmark of any kind — a real, disclosed
0.1.0 evidence gap, not resolved by this validation pass.

## Tolerances and Deviations

- The theoretical-force formula's own piston-area calculation was
  corrected mid-Stage-3/4 (2026-08-27): an earlier Stage 1 conclusion
  wrongly assumed a single-piston area (matching every sibling pneumatic
  sizing module in this project). Corrected once SMC's own primary-source
  catalog text became directly available. This module's own theoretical-
  force formula therefore differs from its siblings' by design, not by
  omission — a genuine mechanical difference between this dual-rod family
  and the round-body/guided families.
- The load-mass-vs-overhang-length band-selection logic (rounding a real
  stroke/speed up to the nearest seeded band) is a new,
  undisclosed-by-SMC engineering judgment call unique to this module.
- The load-mass-vs-overhang-length formula area has no independent
  benchmark of any kind (unlike the theoretical-force formula area) — a
  real, disclosed gap carried into release, not glossed over.
- One digitized curve (graph 10, bore 6, CXS2L speed band) resolves a
  genuinely ambiguous source-table annotation using the best-evidenced
  reading available, disclosed inline for founder confirmation.

## Unsupported Conditions

- Round-body, guided-cylinder, table-cylinder, and rodless variants — each
  is a separate, later module (design doc "Out of Scope").
- The older CXSJ/CXS/CXSW dual-rod sub-families — CXS2L/CXS2M only.
- Any load case (`normal`/`peak`/`holding`/`emergency_stop`) semantics.
- A piston-rod buckling check — SMC's own CXS2 catalog gives no buckling
  formula, and the load-mass-vs-overhang-length rating is this
  mechanism's own governing structural check instead.
- Cushion kinetic energy checked against a candidate's own catalog
  rating — CXS2's own catalog gives no per-model allowable-kinetic-
  energy table.
- Extrapolation beyond every seeded load-mass-vs-overhang-length band —
  reported as out-of-envelope instead.
- A self-serve catalog CSV upload UI.
- Rod-bearing wear, seal life, or a full fatigue/duty-cycle life
  calculation.
