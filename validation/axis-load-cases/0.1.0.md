## Purpose and Supported Applications

Given a linear axis's orientation, incline angle, moving mass (as one
total or a payload/carriage/additional breakdown), Coulomb friction
coefficient, and per-case travel direction/axial acceleration/guide
resistance/external force/moment, this module establishes the applied
loads at the axis's carriage/guide reference point — total moving mass,
gravity resolved into the `axis.v1` coordinate frame, the resultant
applied force and moment vectors, and the signed axial thrust demand — so
downstream modules (ball screw, linear guide, coupling, motor/drive
sizing) can size the motion system, screw, guide, support bearings,
coupling, and drive train from the same load-case evidence
(`context/modules/axis-load-cases/stage-1-spec.md` "Purpose"). It does not
itself claim machine compliance, select a component, or distribute a
moment among individual guide blocks — those remain downstream
responsibilities of the modules that consume its `normal_resultant_force`
/ `normal_resultant_moment` (and `peak_*`) output ports.

`0.1.0` resolves only the `normal` and `peak` load cases. `holding` and
`emergency_stop` are valid `LoadCase` values elsewhere in the engine but
are not implemented here — neither of this module's two accepted
historical fixtures (ID39, ID42; see below) records a holding/brake case
or an emergency-stop case, so there is no evidence to source that
semantics from yet
(`context/modules/axis-load-cases/stage-2-contract.md` "Deferred
Decisions and Release Gates" item 1).

## Validity Envelope and Assumptions

From `lib/modules/axis-load-cases/0.1.0/manifest.ts`
`validityEnvelopeSummary` and `compute.ts`'s recorded assumptions:

- One rigid moving assembly on a straight axis; horizontal, vertical, or
  inclined `0 <= beta <= 90` degrees.
- Only the `normal` and `peak` load cases; `holding` and `emergency_stop`
  are not supported by this version.
- Scalar Coulomb friction coefficient in `[0, 1]`.
- The Coulomb-friction normal load is taken as the gravity component
  perpendicular to the axis of travel (`m_t * g * cos(beta)`); no
  additional normal-load contribution (e.g. from an external force) is
  modeled in this version.
- Explicit, per-case external process force/moment and a center-of-mass
  offset may be supplied; when absent they are treated as zero, not
  inferred.
- Gravity defaults to the parameter registry's standard constant
  (`9.80665 m/s^2`, NIST SP 811 Appendix B.8) when not explicitly
  supplied; the three THK reference examples below instead supply THK's
  own `9.8 m/s^2` catalog convention explicitly, as the `gravity` port
  allows.
- `duty_cycle` and `ambient_temperature` are optional, trace-only usage/
  environment context (`motion.axis.duty_cycle`,
  `env.ambient_temperature`). They are recorded in the calculation
  trace's `usage-context` step when supplied but never enter a load-case
  force/moment equation — proven by
  `lib/modules/axis-load-cases/0.1.0/package.test.ts`'s "usage and
  environment context" tests, which assert every normal/peak force and
  moment output is byte-for-byte identical with and without these two
  inputs supplied.
- No structural compliance, backlash, guide-block load distribution,
  collision impact, regenerative braking, brake sizing, or legal/
  regulatory compliance claim is made anywhere in this module or record.
- Out of scope for this version: holding case, emergency-stop case, a
  third long-stroke/high-speed real-project fixture (see "Tolerances and
  Deviations" below).

## Reference Examples (Published Worked Examples)

All three examples are reproduced through the real module compute path
(`executeModule(axisLoadCasesModule, ...)`), not a bare kernel call, in
`lib/modules/axis-load-cases/0.1.0/thk-reference-examples.test.ts`. All
three supply THK's own `g = 9.8 m/s^2` convention explicitly via the
`gravity` port, not this module's NIST-derived `9.80665 m/s^2` default.

### Example 1 — THK B15-72 (horizontal)

- Source: `jp.thk.example_ball_screw_selection@515-1e`, "Example Ball
  Screw Selection" chapter, p. B15-72
- Inputs: horizontal axis (`beta = 0`), `m = 80 kg`, `mu = 0.003`, guide
  resistance `f = 15 N`, `Vmax = 1 m/s`, `t = 0.15 s`
  (`a = 1/0.15 = 6.666666666666667 m/s^2`), `g = 9.8 m/s^2`
- Published/expected result: `550 N` (acceleration) / `17 N` (constant
  speed) / `-516 N` (deceleration)
- MachineStudio result: `550.685 N` / `17.352 N` / `-515.981 N`
- Difference: `0.685 N` (acceleration) / `0.352 N` (constant speed) /
  `0.019 N` (deceleration) — maximum absolute difference `0.685 N`
- Tolerance applied and why: `±1 N` — whole-newton catalog rounding,
  matching THK's own printed precision at `g = 9.8 m/s^2`
- Pass / fail against tolerance: **pass** (all three within `±1 N`)

### Example 2 — THK B15-86 (vertical)

- Source: `jp.thk.example_ball_screw_selection@515-1e`, same chapter,
  p. B15-86
- Inputs: vertical axis (`beta = pi/2`), `m = 50 kg`, `mu = 0` (no
  friction coefficient stated), guide resistance `f = 20 N`,
  `Vmax = 0.3 m/s`, `t = 0.2 s` (`a = 1.5 m/s^2`), `g = 9.8 m/s^2`
- Published/expected result: `585 N` / `510 N` / `435 N` (acceleration /
  constant speed / deceleration, upward)
- MachineStudio result: `585 N` / `510 N` / `435 N`
- Difference: `0 N` on all three (exact match)
- Tolerance applied and why: `±1 N` — whole-newton catalog rounding
- Pass / fail against tolerance: **pass**

### Example 3 — THK B2-22 (vertical)

- Source: `jp.thk.example_ball_screw_selection@515-1e` (citation-
  granularity note above), "Example of Calculating the Nominal Life"
  chapter, p. B2-22
- Inputs: vertical axis (`beta = pi/2`), `m = 30 kg`, `mu = 0`, guide
  resistance `f = 10 N` (**algebraically derived**, not independently
  published: the source states only the `304 N` constant-speed figure
  and `F = m*g + f`; `f = 304 - 30*9.8 = 10 N` is back-solved from that
  published result, recorded here rather than treated as an
  independently-sourced input), `a = 2.4 m/s^2`, `g = 9.8 m/s^2`
- Published/expected result: `376 N` / `304 N` / `232 N` (acceleration /
  constant speed / deceleration, upward)
- MachineStudio result: `376 N` / `304 N` / `232 N`
- Difference: `0 N` on all three (exact match)
- Tolerance applied and why: `±1 N` — whole-newton catalog rounding
- Pass / fail against tolerance: **pass**

## Independent Method or Tool Comparison

- Independent method/tool: Atlanta Drive Systems, "Rack and Pinion Drive
  Calculations and Selection," pp. C-53–C-55
  (`us.atlanta_drive_systems.rack_pinion_calculations@sha256-2bc6e48c2dce79dd`)
  — a rack-and-pinion drive manufacturer's method, a distinct
  transmission mechanism from THK's ball screw, sourcing its own two
  worked examples as an independent implementation in
  `lib/modules/axis-load-cases/0.1.0/atlanta-benchmark.ts`
  (`resolveAtlantaHorizontalForce`, `resolveAtlantaVerticalForce`),
  tested in `atlanta-benchmark.test.ts`.
- Case(s) compared: p. C-54, horizontal, friction-resisted
  (`Fu = m*g*mu + m*a`; `m = 820 kg`, `mu = 0.1`, `v = 2 m/s`, `t = 1 s`,
  `g = 9.81 m/s^2`); p. C-55, vertical, lifting
  (`Fu = m*g + m*a`; `m = 300 kg`, `v = 1.08 m/s`, `t = 0.27 s`,
  `g = 9.81 m/s^2`).
- Result from independent method: horizontal published `2.44 kN`
  (`2440 N`); vertical published `4.1 kN` (`4100 N`).
- MachineStudio result: `resolveAtlantaHorizontalForce` computes
  `2444.42 N`; `resolveAtlantaVerticalForce` computes `4143 N`. Both are
  also cross-checked in the same test file against this module's own
  `resolveAxisLoadPhase` kernel for the equivalent reduced scenario (no
  guide resistance, external load, or center-of-mass offset; horizontal
  reduces to `incline = 0`, vertical to `incline = pi/2`): the two
  independently-authored implementations agree to floating-point
  precision (`toBeCloseTo(..., 9)`).
- Difference and explanation: horizontal `4.42 N` (`0.181%`); vertical
  `43 N` (`1.049%`). Both differences are attributable to Atlanta's own
  coarser catalog rounding (2–3 significant figures in its published
  `kN` results), not a formula disagreement — the exact
  floating-point agreement between the two independently-authored
  implementations for the equivalent reduced scenario confirms the
  shared physics is implemented identically; only the source's own
  published rounding differs from the unrounded computation.

This benchmark validates only the shared Newtonian/gravity/Coulomb-
friction mechanics the two methods have in common; it does not exercise
ball-screw-specific mechanics (lead-angle efficiency, preload friction
torque) that THK's method separately covers, so it is a partial, not
full-coverage, benchmark.

Per `context/ai-workflow-rules.md` "Stage 4 — Validation," this
comparison serves as the solo-validation reviewer substitute recorded
below: no second engineer was available for this release.

## Unsupported Conditions

- `holding` and `emergency_stop` load cases are not implemented in this
  version. Neither ID39 nor ID42 contains a holding/brake case or an
  emergency-stop case, so there is no evidence to source their semantics
  from yet.
- No structural compliance, backlash, guide-block load distribution,
  collision impact, regenerative braking, or brake sizing is modeled.
- This module and record make no legal or regulatory compliance claim;
  passing its checks does not certify the whole machine against any
  cited source.
- Only one rigid moving assembly on a straight axis is supported —
  horizontal, vertical, or inclined `0–90` degrees; no multi-body or
  flexible-assembly treatment.
- Scalar Coulomb friction only, in `[0, 1]`; no velocity-dependent or
  Stribeck friction model.
- `duty_cycle` and `ambient_temperature` are trace-only context: no
  duty-cycle-based force averaging/derating and no temperature-based
  derating is applied by this module — a manufacturer-specific derating
  formula, if needed, belongs to the module that owns its source method.
- ID39 and ID42 are accepted `0.1.0-release-candidate` regression
  evidence, not release-grade vendor-sizing validation — see "Tolerances
  and Deviations" above for the specific provenance gaps and known
  discrepancies that remain open.
- The third long-stroke/high-speed real-project fixture required by the
  broader Unit 0.1 / Phase 1B validation program is not yet available and
  is not represented by any evidence in this release.

## Supported Use Limits (Summary)

`axis-load-cases` 0.1.0 resolves the `normal` and `peak` load cases only,
for one rigid moving assembly on a horizontal, vertical, or inclined
(`0–90` degree) straight axis, with scalar Coulomb friction in `[0, 1]`,
explicit per-case external process force/moment and center-of-mass
offset, and trace-only (non-force-altering) duty-cycle/ambient-
temperature context. It is validated against three published THK worked
examples (all passing within `±1 N` whole-newton catalog rounding) and
one independent rack-and-pinion benchmark from a second manufacturer
(Atlanta Drive Systems; both cases passing within the source's own
catalog-rounding tolerance, and the independent implementation agreeing
with this module's own kernel to floating-point precision). ID39
(horizontal) and ID42 (vertical) historical project fixtures are accepted
as `0.1.0-release-candidate` regression evidence with documented
provenance gaps, not release-grade vendor validation. `holding`,
`emergency_stop`, structural compliance, backlash, guide-block load
distribution, collision impact, regenerative braking, brake sizing, and
any legal/regulatory compliance claim are explicitly out of scope for
this version.
