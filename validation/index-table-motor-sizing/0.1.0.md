## Purpose and Supported Applications

Given a rotary index table's own table geometry and mass, any additional
mounted-load inertia, gear ratio, and one commanded index move (a fixed
angle rotated in a fixed time, standstill to standstill), computes the
required motor specifications: acceleration torque, maximum momentary
torque, required torque with an engineer-supplied safety factor, operating
speed, required power, total reflected system inertia, and inertia ratio.
Reports required-spec values and pass/fail checks against
engineer-supplied margins, the same scope every prior Motor Sizing Tool
module already established. Does not check motor catalog matching or
model discrete mounted-load geometry (ADR-0011 "Output scope";
`stage-2-contract.md` "Decisions" item 4).

## Validity Envelope and Assumptions

- One rotary index table: one rigid, disk-shaped table rotating about its
  own axis, direct-connected or through a single fixed gear ratio. Any
  mounted workpieces/fixtures are one combined engineer-supplied inertia
  value, not modeled as discrete geometry.
- One index move: a single accelerate-decelerate-to-stop event from
  standstill back to standstill, covering a commanded angle in a
  commanded time — not a repeating duty cycle.
- `load_torque` is a required, engineer-supplied input defaulting to `0`
  — not computed by this module (both primary sources independently omit
  a formula for it).
- Self-contained per ADR-0011 "Reuse policy": reproduces, rather than
  imports, Oriental Motor Co., Ltd.'s and AutomationDirect's own
  index-table sizing methods. The one genuine import is
  `lib/engine/mechanics` (Unit 6.1).
- No stepping-motor-specific pulse/resolution modeling and no motor
  catalog matching.

## Reference Examples (Published Worked Examples)

**AutomationDirect's own "Index Table - Example Calculations" (pp.
B-14-B-16)**, reproduced through the real `executeModule` compute path
(`automationdirect-reference-example.test.ts`): a 12 in diameter, 3.25 in
thick steel table, 6:1 gear reducer, indexing `45 deg` in `0.5 s` (`25%`
accel fraction), selected motor SVM-220 (`J_motor=0.014 lb-in-sec^2`).

- `table_inertia` matches the printed `Jtable=4.80 lb-in-sec^2` within
  `0.3%`; `reflected_load_inertia` matches the printed
  `0.133 lb-in-sec^2` within `0.5%`; motor-shaft `operating_speed`
  matches the printed `121 rpm` within `1%` (using the source's own
  stated `25%`-of-index-time accel fraction computed exactly rather than
  its own further-rounded `0.13 s` printed intermediate); `inertia_ratio`
  matches the printed `9.5` within `0.5%`.
- `acceleration_torque`/`momentary_torque` do **not** match the source's
  own printed `13.68 lb-in` figure at face value (confirmed by test to
  differ by `5%-12%`, a real and expected gap). Every worked example in
  this source document computes acceleration torque with a rounded `0.1`
  constant standing in for the exact `2*pi/60=0.10472` (confirmed by hand
  against the same document's own Example 7, which uses the unrounded
  form and reproduces its own printed figure only that way). This
  module's own kernel uses exact physics throughout. Reapplying the
  source's own rounded constant and its own further-rounded intermediate
  values (`121 rpm`, `0.13 s`) at the test level reproduces its own
  printed `13.68 lb-in` figure within `0.5%`, proving the deviation is
  fully explained by that one disclosed convention choice.

**Oriental Motor Co., Ltd.'s own "Index Table -- Using Stepping Motors"
(pp. F-8-F-9)**, reproduced at the **kernel level**
(`oriental-motor-reference-example.test.ts` -- not `executeModule`, since
`attached_load_inertia` takes one pre-resolved figure): a `300 mm`
diameter, `10 mm` thick steel table plus 12 discrete steel workpieces
(`40 mm` diameter, `30 mm` thick) mounted at a `125 mm` radius, `7.2:1`
gearhead, indexing `30 deg` in `0.3 s` (`25%` accel fraction, a clean
value with no further source-internal rounding).

- The fixture's own 12-workpiece parallel-axis inertia sum (computed with
  `lib/engine/mechanics`' `pointMassInertia`/`offsetAxisInertia`, exactly
  mirroring the source's own `JC+m*l^2` per-workpiece method) matches the
  printed `JW=3118 oz-in^2` within `1%`.
- `table_inertia` (via `resolveTableInertia`) matches the printed
  `JT=3442 oz-in^2` within `1.5%`; the summed `load_inertia` matches the
  printed `JL=6560 oz-in^2` within `1.5%`.
- Table-shaft operating speed (via `resolveOperatingSpeed` at
  `gear_ratio=1`) matches the printed `N=22.2 r/min` within `0.5%`.
- **Not reproduced, a disclosed scope limitation:** this example's own
  final acceleration-torque and required-torque figures. It sizes a
  stepping motor with a pulse-speed-based acceleration-torque convention
  (`Ta = (J0+i^2*JL)/g * (pi*Nm/180) * (f2-f1)/t1`) materially different
  from this module's own continuous rad/s `Ta = J*alpha`, and the source
  page's own printed formula for that step is OCR-degraded past reliable
  hand-verification in this environment (the available mirror is a
  scanned/image PDF).

## Independent Method or Tool Comparison

**Satisfied (2026-08-13).** `independent-benchmark.test.ts` cross-checks
this module's own six-function kernel (`resolveTableInertia`,
`resolveLoadInertia`, `resolveReflectedLoadInertia`,
`resolveTotalSystemInertia`, `resolveOperatingSpeed`, `accelerationTorque`)
against a single combined expression reimplementing AutomationDirect's own
general "Belt (or Gear) Reducer Equations" formula
(`Jtotal = Jmotor + (Jload/i^2)`), written independently in
`independent-benchmark.ts` -- the same "structurally separate
reimplementation, proved identical" pattern every prior Motor Sizing Tool
module's own independent benchmark already establishes.

- Independent method/tool: a single-expression reimplementation of the
  full inertia-to-acceleration-torque chain.
- Case(s) compared: one hand-verified scenario (AutomationDirect's own
  index-table example, `i=6`), plus a deterministic 300-scenario property
  sweep (table mass/diameter, attached-load inertia, gear ratio, motor
  rotor inertia, and index angle/time/acceleration-time all varied).
- Result: agreement to floating-point precision (`< 1e-9` relative
  difference) across every scenario -- an algebraic identity, not an
  approximation.

## Tolerances and Deviations

- AutomationDirect's own worked examples compute acceleration torque with
  a rounded `0.1` constant standing in for the exact
  `2*pi/60=0.10472` (confirmed against the same document's own Example 7,
  which uses the unrounded form). This module's own kernel uses exact
  physics throughout, consistent with every other module in this
  codebase, so its own torque outputs are systematically `~4.7%` higher
  from the constant alone, compounding with the source's own further
  intermediate rounding to a total `~8%` difference from its own printed
  figures -- fully explained and reapplied exactly at the test level (see
  "Reference Examples" above), not an unexplained residual.
- A genuine unit-convention difference between the two primary sources,
  disclosed rather than silently reconciled: Oriental Motor's own printed
  `oz-in^2` inertia figures are mass-based (`oz` used as a mass unit,
  confirmed by cross-checking the source's own printed
  `oz-in^2`-to-`kg*m^2` conversion on the same page), while
  AutomationDirect's own `lb-in-sec^2` figures are weight-based, requiring
  the explicit `/g` division its own formula shows. Both are legitimate,
  internally consistent conventions within their own documents; this
  module's own kernel works entirely in SI mass-based units throughout, so
  no ambiguity reaches the kernel itself.

## Unsupported Conditions

- Discrete point-load geometry (count, radius, individual mass) -- the
  engineer supplies one combined `attached_load_inertia` figure instead.
- A repeating duty cycle or effective (RMS) torque check.
- Stepping-motor-specific pulse-speed/resolution modeling.
- Motor catalog matching or part selection.
- Oriental Motor's own final acceleration-torque/required-torque figures
  -- a disclosed, out-of-scope gap (stepping-motor pulse-speed
  convention, OCR-degraded source page).
- No `linear-axis@1` or other guided-workflow role -- standalone in
  `0.1.0` (ADR-0011).

## Supported Use Limits (Summary)

One rotary index table, one rigid disk-shaped table, an optional
engineer-supplied mounted-load inertia (default `0`), direct-connected or
single-fixed-gear-ratio, one index move commanded directly in angle/time,
one required safety factor (`>= 1`) and one required maximum inertia
ratio, no built-in defaults. `load_torque` is a required, engineer-supplied
input defaulting to `0` per both primary sources' own independent
omission of a formula for it. Validated via AutomationDirect's own
published worked example (fully reproduced, with its own torque-figure
gap precisely quantified and disclosed) and Oriental Motor's own published
worked example (partially reproduced at the kernel level, inertia and
speed only), plus a 300-scenario independent-benchmark property sweep.

the fifth and last mechanism module in the Motor Sizing Tool family
